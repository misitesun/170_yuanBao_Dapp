# 抢拍卡牌

活动配置按enabled字符串和can_buy判断参与权限，时间仅展示服务端buy_start/buy_end；旧phase/server_time已移除，不根据本机时间判断尚未开始。配置进入/手动重试读取。库存stock小于1只Toast提示已抢购完，不显示库存数字、不禁用缺货按钮。抢拍调用POST /api/orders/buy，每次一张，只提交product_id，同步ref防重，提交中禁用按钮。成功显示抢拍成功并重新读取商品/配置，刷新用户余额独立处理错误，不能改报抢拍失败。

2026-10-10 商品展示已接入公开 GET /api/products，本段覆盖下方历史静态商品说明。首页轮播和缩略图使用接口数量、顺序、name/image/price；抢拍列表使用 name/image/purch_usdt/purch_bao。金额保持字符串，图片地址保留原值，按开发者确认的商品 ID 选择背景：1 红色典藏、2 蓝色尊享、3 绿色至尊，未知 ID 回退蓝色；卡牌图片始终来自接口 image，不用本地卡图替换。加载、空列表、失败重试由真实请求状态决定，卸载中止请求。购买/抢拍仍只提示待接入，参与时间已使用 /api/orders/config，不启用下拉刷新。

`AuctionPage` 对应 `/auction`，复用 MainLayout 和公共 Header。首页进入抢拍与侧栏抢拍卡片均到达此路由；侧栏点击沿用原有关闭行为。

数据来自Figma静态稿：三种卡牌、价格与每日参与时段，不视为支付参数或库存。立即抢拍显示待接入Toast，不发起API、授权或合约交易。没有数据加载，不启用下拉刷新。

尺寸、字体、颜色、布局与资源核对见 `docs/yuanbao-auction-checklist.md`。正文用Grid/Flex正常流；仅页面背景为非交互定位装饰。页面私有背景与价格图标在 `src/assets/auction/`，共享卡牌、时钟和抢拍按钮在 `src/assets/common/`，与首页引用同一份文件。

开发者确认页面默认使用微软雅黑，替代设计的Alibaba PuHuiTi/PingFang SC。字号、字重、行高与字距仍采用Figma读取值；平台未安装微软雅黑时由系统sans-serif回退，不声称字形与原稿完全相同。Header继续沿用现有公共样式。

## 多语言

固定文案、状态和无障碍标签接入五种语言，静态数值与交互边界保持。说明与富文本标题的处理见 docs/yuanbao-i18n-checklist.md。

2026-09-30 展示术语按 `PROJECT_TERMS.md` 统一：固定文案中的 USDT 显示为“余额”，并使用五种语言对应译文；内部资产标识、选择器值、字段名和后端原文保持原值。该规则覆盖本文历史展示文案说明。

立即抢拍先打开共享Popup二次确认，展示点击时的卡名、每次1张及余额/宝气扣款金额快照，沿用首页毛玻璃确认样式。取消不请求；确认再次检查当前商品库存及can_buy，才提交product_id。同步防重，提交中禁用取消并拒绝关闭，失败保留确认弹窗供重试，成功关闭并刷新。

后台尚未配置图片时接受image空字符串，不进行HTTP/图片加载探测，不添加onError判断或替代图片；渲染时空src省略以避免React警告。首页卡包保留logo位置，不以#ID替代空图片。

提交反馈统一规则：保持按钮原文案，提交期间禁用重复操作，并通过 ContractLoading 显示全屏水滴遮罩；结束后关闭遮罩。提交结果只通过 Toast 提示，公共 HTTP 错误已提示时不重复提示，不在表单/页面插入提交状态或错误文本。原请求参数、确认步骤与成功后的数据刷新保持。

2026-10-10 加载展示规则：普通页面读取静默等待，不显示水滴或替代加载文字，保留loading门控，不把未完成的读取显示为空列表；请求结束后保留原数据/空状态/错误重试。业务提交仍使用ContractLoading，已有追加分页仍使用公共水滴，接口和操作逻辑保持。
