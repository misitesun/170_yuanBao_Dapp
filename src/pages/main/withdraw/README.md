# 提现

`WithdrawPage` 对应二级静态路由 `/withdraw`，资产页提现按钮通过 `useAppNavigate` 进入；路由位于MainLayout外，复用SecondaryHeader的顶部、返回及右插槽，不新增双Header或改变侧栏契约。设计源为Figma 29534:12621，精确量测、资源核对和适配差异见 `docs/yuanbao-withdraw-checklist.md`。

保留信息卡→提现数量→手续费→提交按钮的正常流布局。GET /api/claims/config 登录加载开关、最低额度、手续费百分比；最低额度不常驻展示，仅提交数量低于该值时通过Toast提示。配置未就绪或关停禁用提交，失败可重试，卸载取消。余额来自已验证session.user.balances.usdt，全部填入原字符串。提现链固定BSC20，不可切换；币种保留余额（内部USDT）。

POST /api/claims 仅传ccy=balance_usdt和字符串amount；6位截断后精确校验正数、最低额度及余额。页面调用 claims/flow 的 executeClaim，接口返回的签名参数经严格解析后交给 YBProject.withdraw，等待成功回执才提示提现成功。复用 useSyncExternalStore 观察账户隔离的内存状态，同步门控防止双击，忙碌阶段禁用按钮和数量修改。账户/网络预检在申请前执行，申请后再次核对账户。无ERC20授权。

拒签或明确回执回退保留提取单，按钮保持“提现”，只重试合约，不重复扣余额。未知链上错误再次点击“提现”时仅查询同一id的usedWithdrawIds，不重新发交易。过期同样只能检查结果，不能重新申请。申请成功但参数异常或申请响应丢失时锁住重复申请，提示联系平台核对。HTTP 4xx/5xx 响应失败后恢复按钮和输入，允许重试；公共 HTTP 已提示的错误不再显示页面 Toast。成功后可点“提现”清空完成状态，开始新单。签名状态跨路由保留但不跨整页刷新，当前没有恢复/重新签名接口，需后台核对后处理。页面离开不回写本页状态；后续进入可看到内存中的进度。

后台扣款与链上领取分开处理，申请已成功即使拒签也刷新用户余额；刷新失败使用独立提示。仍固定BSC20展示、不开放链选择，实际开发调用链由既有测试部署配置31337决定，不把BSC20展示文案作为切链依据。记录入口不变，记录页仍未接真实接口。契约见docs/yuanbao-claims-contract.md。

主题配色全部引用现有公共token，布局用正常流和Flex，无页面定位例外。记录及箭头与充值页资源一致，复用其完整SVG，保持导出根尺寸；不重绘。字体沿用微软雅黑，未暴露的行高39/34px属于记录在清单中的排版估算。输入103px、圆角20px，按钮88px、圆角999px，使用共享渐变焦点描边与full-button mixin，恢复源设计输入→手续费→按钮的间距。充值页仍保留其原有排除规则。

## 多语言

固定文案、状态和无障碍标签接入五种语言，静态数值与交互边界保持。说明与富文本标题的处理见 docs/yuanbao-i18n-checklist.md。

2026-09-30 展示术语按 `PROJECT_TERMS.md` 统一：固定文案中的 USDT 显示为“余额”，并使用五种语言对应译文；内部资产标识、选择器值、字段名和后端原文保持原值。该规则覆盖本文历史展示文案说明。

提现结果反馈仅使用 Toast：成功回执显示“提现成功”，非 HTTP 领取异常显示“提现失败”；公共 HTTP 已提示时不叠加。领取状态和 RPC 错误不渲染到表单，配置失败仅保留重新加载入口。内部签名与防重复领取状态继续保留。

提交按钮始终保持“提现”文案，提交与账户检查、接口申请、链上领取/核对、余额刷新期间通过 ContractLoading 复用全屏水滴遮罩。遮罩由 busy 控制，finally 结束本页提交状态；不使用按钮文案展示阶段，也不改变原领取单重试规则。

数量输入与“全部”仅在 busy 处理期间禁用，失败后可修改。表单编辑不重置已有签名领取单：ready/uncertain/expired 继续原单领取或核对，不把编辑后的数量用于再次申请，避免重复扣款；只有新的 idle 申请使用当前输入。
