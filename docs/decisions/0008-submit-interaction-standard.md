# ADR 0008：统一提交反馈与链上恢复边界

- Status: Accepted
- Date: 2026-10-10

## 背景

开发者明确要求所有提交同步提现交互：按钮不改变文案，点击后禁用，水滴加载遮罩，成功/失败 Toast，不在页面增加提示文本；失败后输入恢复可编辑。已签名领取单还必须避免重复申请扣款。

## 决策

将通用行为集中到 docs/submit-interactions.md，由 AGENTS、协作流程、五个本地开发/审查 skill 以及 API/合约文档入口引用。复用 ContractLoading、Toast 和集中 HTTP/DApp 边界，不新建通用交易执行器。用户修改输入不改变原服务端签名；HTTP 失败、无响应、拒签与链上未知结果按当前契约分别恢复。

## 后果与验证

后续开发必须验证同步防重、原文案、水滴遮罩关闭、Toast 去重、失败输入恢复、签名原值与同单重试。HTTP 500 不被推广为通用的未扣款证明。具体接口与部署事实留在实际项目，模板仅记录通用规范。本次为文档与 skill 更新，不修改运行时实现、不执行真实钱包操作。
