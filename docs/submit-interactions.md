# 提交接口与链上交互规范

确认日期：2026-10-10。适用于所有真实业务提交（POST/PUT/PATCH/DELETE、写合约、钱包授权/重新授权），以及后续基于本模板的新功能。普通页面首屏、详情、配置与会话校验读取不显示水滴动画；保留加载门控与aria-busy，不能提前显示空数据。追加分页继续使用水滴；下拉刷新保留现有刷新组件提示。具体接口、链、地址、精度和权限必须来自当前项目文档，本规范不提供业务默认值。

## 固定交互

- 校验失败通过现有 Toast 提示，不发送请求；设计已有二次确认时，确认后才执行真实提交。
- 真正提交前同步置 ref 锁，再设置 submitting 状态；按钮原生 disabled（ActionButton 的 loading 可作为门控），快速双击只能产生一次操作。
- 保持原按钮文案及页面文案。不切换为“处理中”“继续领取”“检查领取结果”等阶段文案，不在页面或确认弹窗内容中插入提交错误、RPC 错误、状态说明或失败提示段落。
- 提交期间使用共享 ContractLoading 水滴全屏遮罩（内部复用 Popup + DropletLoading），禁止遮罩点击关闭；不要自己绘制 spinner 或依靠按钮改文案表示等待。
- 提交遮罩放在确认 Popup 的同级，确保确认弹窗关闭后仍能覆盖必要的等待。只挂载一个本次提交遮罩；结束、异常或卸载时释放状态和滚动锁，不让遮罩永久驻留。
- 普通输入和“全部”仅在处理期间 disabled；失败后恢复可编辑。保留输入供用户修改，不把非 busy 业务进度等同于表单永久禁用。
- 结果通过现有 Toast：成功使用 success，失败使用 error；不增加另一套结果弹窗。结果提示必须在遮罩关闭后可见，或经既有展示机制保证可见，不能在遮罩下超时消失。
- 公共 HttpErrorToast 已展示的错误先用 wasHttpErrorReported(error) 判断，页面不要再次提示，包括先读取流程 message 再重复 Toast 的分支。钱包/RPC 等非 HTTP 错误使用简短的业务失败提示，技术栈、RPC 原文和内部诊断不写入页面。
- 所有退出路径通过 finally 或等效结构解除提交锁；卸载、换账号后的旧请求不得写回当前页面或当前账户。提交期间禁用整屏下拉刷新。

## 接口与成功响应

- HTTP 由 services/http 集中处理，feature 管理已确认的请求字段与必要解析，页面不得直接使用 Axios。参数校验、币种、库存、开关、余额和时间权限以对应契约为准。
- 前端只需要 HTTP 成功时，feature 返回 Promise<void>，await request<unknown>(...)；不解析、解构或校验未使用的成功响应。空或不兼容的成功体不能制造提交失败。
- 成功体用于立即调用合约、跳转、后续请求或下载时，只严格校验已文档化且实际消费的字段。服务端签名字段原样保存，不能降低校验来让调用通过。
- 提交成功与读取刷新使用独立错误边界。刷新失败不是提交失败，不能诱导用户再次执行已完成写入；公共读取错误不重复提示，局部提示如确有必要应明确指出刷新失败，不插入页面文本。
- API-only 流程以请求成功为成功；API + 链上流程需先完成全部必需步骤，不能仅 POST 成功就提示最终提现/领取成功。

## 链上调用

- 通用 provider、wallet、viem、ERC20 和回执服务留在 services/dapp；项目 ABI、env 地址及业务封装留在 services/contracts，API 与领取编排留在 feature。页面不直接读 window.ethereum 或引入 viem。
- 申请前核对当前钱包账户和合约目标链；申请返回后、发交易前再次核对账户。链与地址来自当前部署/env，不根据“BSC20”等展示文案猜测实际测试链；没有授权时不自动切链。
- 后台返回的 token、整数 amount、签名和 deadline 保持原值，仅按 ABI 做必要 bigint 转换。签名金额不再次乘 decimals，不用 Number/浮点数重构，不覆盖 token 为前端固定地址，不延长过期时间。
- 只有业务契约要求时才授权 ERC20 或传 native value，不能因为存在 MockUSDT 就自动 approve。提现 ABI 是 nonpayable 时不附 value。
- 等待 writeDappContract 的成功回执后才认定链上成功，拒签、回退和查询错误必须关闭本轮遮罩。
- 依赖 msg.sender 的 read 显式传 connected account；公开状态/Token 元数据读取不强制传 account。新增调用必须核对 ABI 与当前文档。

## 失败恢复与签名单

表单解锁与业务重试授权是两个独立条件。后台可能在签发领取参数时已扣余额；让输入可编辑不代表可以丢弃签名再扣款。

- 接口明确失败后按当前接口契约恢复可重试状态；HTTP 500 不能被当成通用“必定未扣款”证明。本项目允许的重试策略要在 feature 文档中注明，不能推广到其他金额接口。
- 无响应、请求结果不明、HTTP 成功但签名参数异常时，不推断“没有扣款”；保留恢复状态，依据已文档化的查询/恢复机制核对，不自动重复 POST。
- 已获取的签名单按钱包账户隔离保存。拒签或明确交易回退可重试原单，不再次申请。修改表单的金额不改变已签名金额，也不重新生成原单；新申请仅在原流程已完成或后台提供明确恢复/取消依据后进行。
- 未知链上结果只通过已文档化的状态读取核对，不能自动重复发交易；签名过期不自行重新签名、延长 deadline 或发新扣款请求。
- 页面离开后保留原单与否、刷新浏览器能否恢复，必须在当前 feature 文档说明。缺少查询/重新签名/取消接口时如实记录，不编造恢复能力，不把内部诊断常驻显示在 UI。

## 验收

- 快速双击只请求/发交易一次，提交期按钮 disabled，原文案保持，水滴遮罩可见。
- 成功、HTTP 4xx/5xx、无响应、钱包拒签、交易回退和查询失败均结束本轮等待；失败后输入/全部恢复可编辑，已有签名按规则保留。
- 每次提交只展示其所属结果反馈，公共 HTTP 与局部 Toast 不重复，页面没有提交状态/错误文本，遮罩不吞掉结果提示。
- 未使用响应体为空/类型不兼容仍成功，真正 HTTP 失败仍 reject；必需签名字段异常禁止调用合约。
- 刷新失败不改报提交失败；钱包换账号/错链/卸载不回写旧结果。签名原值与 ABI 顺序、大整数及同单重试不重复 POST 有回归测试。
- 用 pnpm 运行聚焦测试、项目质量门禁和 git diff --check；区分 mock/构建通过与真实钱包、链上回执、索引同步验收。
