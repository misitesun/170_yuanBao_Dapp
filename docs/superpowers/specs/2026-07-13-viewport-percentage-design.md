# Viewport Pixel and Percentage Design

## Goal

Add explicit helpers for converting 750-design dimensions to physical CSS pixels required by third-party components, plus an exact clamped integer percentage calculator.

## Public API

```text
src/shared/viewport/
├── getViewportWidthPx.ts
├── getViewportHeightPx.ts
└── README.md

src/shared/calculations/
├── calculatePercentage.ts
└── README.md (updated)
```

- `getViewportWidthPx(designPx, designWidth = 750): number` reads `window.innerWidth` once per call and calculates `innerWidth × designPx ÷ designWidth`.
- `getViewportHeightPx(designPx, designHeight): number` reads `window.innerHeight` once per call and calculates `innerHeight × designPx ÷ designHeight`.
- Neither viewport function installs listeners or reacts to later viewport changes. In React, one-time page-entry values use `useState(() => getViewportWidthPx(...))`.
- Without `window`, viewport functions use the corresponding design dimension as the viewport dimension, so the result equals `designPx`.
- Invalid, empty, non-finite, negative design pixels, or non-positive design dimensions return `0`.
- `calculatePercentage(currentValue, totalValue): number` strictly validates both values, requires current >= 0 and total > 0, uses `divideDecimalNumbers()` and `multiplyDecimalNumbers()`, truncates toward zero, and clamps the result to 0–100.

## Important Distinction

PostCSS `px → vw` conversion is width-based. `getViewportHeightPx()` is a separate explicit height-ratio helper and is not equivalent to CSS generated by PostCSS.

## Verification

Tests cover 750/375 width conversion, custom design dimensions, SSR fallback, invalid values, one-read-per-call behavior, exact huge percentage inputs, fractional truncation, invalid/empty/negative/zero values, and the 100 cap. All tests, Oxlint, TypeScript, and Vite build must pass.
