# 买卡与抢购数量契约

来源：开发者提供《元宝卡买卡抢购接口.md》，2026-10-12。本文仅记录本次数量接入范围。

- 买卡：Bearer 登录 POST /api/orders/sell，JSON product_id（整数≥1）、quantity（可选整数1–100，不传为1），先检查公开 GET /api/orders/config 的 can_sell。扣元气单价 × quantity，每张生成一个订单，产品销量及库存增加quantity。
- 抢购：Bearer 登录 POST /api/orders/buy，同样字段和数量约束，先检查can_buy。扣USDT单价 × quantity及宝气单价 × quantity；每张一个订单，库存减少quantity。每种资产按总额一次扣款。
- 数量或余额不足整单失败，不部分成功。抢购stock=0提示“该产品已抢购完”；库存或全平台今日额度不足统一提示“可抢数量不足”，替代旧提示“抢购数量超过今日买入数量”。不推断未提供的全平台额度字段。
- 成功HTTP200空数组[]，无订单号。前端仅消费HTTP成功，方法返回Promise<void>，不解析响应体。400业务失败为纯文本，401登录失败，422产品ID/数量校验失败，500内部错误，沿用公共HTTP处理。
- 页面复用确认Popup与Input，数量默认空、由用户输入整数数量、精确总额预览；取消不请求。确认先校验1–100，抢购再校验已加载stock；服务端负责最终权限、库存、当日额度与余额。
- 提交同步防重、禁用输入与操作、ContractLoading遮罩、结果仅Toast。失败恢复输入并保留数量，不自动重复POST；成功关闭弹窗并分别刷新权威读取与余额，刷新失败不改报提交失败。
- 测试覆盖数量边界、两接口JSON参数、未消费响应、总额精度、重复点击、库存不足、失败恢复与刷新错误边界。测试和构建不证明真实扣款。
